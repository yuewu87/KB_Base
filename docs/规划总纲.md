## 一、需求

### 定位

**人机共用的知识库，但偏 AI。** 人这一侧只用 Obsidian 做三件事：查看、检索、手写「用户的判断」。会话里的 AI 是主要使用者，直接查。

### 核心

**知识的关联性和检索能力。** 不是「放对位置」本身——放错位置可以接受。

### 两层

| | 是谁 | 干什么 |
|---|---|---|
| **第一层** | 会话 AI（Claude Code、DeepSeek Harness） | **只**投递、发请求、接收 |
| **第二层** | 知识库服务 | 处理请求、分发、检索、返回 |

### 边界

- 个人使用，无协作
- 内容外发不介意（介意的话换本地 LLM）
- 实现代码、数据、相关文件全在本仓库
- 最终要能打包成可移植项目

### 第 7 条的边界（有反面教材）

调研查到 Graphiti（Zep）的失效机制在生产上出过事故：**被自动失效的事实里 70% 其实还是真的**。原因是它挑「哪些旧事实该失效」时用语义相似度、**不要求候选与新事实共享同一个实体**，然后一次 LLM 调用返回裸索引，系统照时间戳算术直接落。结果**只是用词相近**的两条会互相误伤，常见形态是「更窄的新结论废掉更宽的真结论」。

**所以我们的做法：**

- 失效**由会话层显式指定**（`--revise`），**不由服务靠相似度猜**
- 失效内容**保留**，但**默认不进检索结果**
- 失效判断**要留痕**（Graphiti 的另一个缺陷是它不留可复核记录）——整理日志天然覆盖

### 第 10 条的含义

**没有管理 agent，没有 agent 之间的对话。** 从「会话层请求」到「结果返回」是一条链：每一步是确定的，LLM 只在固定的调用点上工作（规划、审核判断、标题提炼）。

这同时回答了「审核跑在哪个进程」——**在服务内，是链上的一步**。规则只有一份，改一处全生效。

### 第 10 条的代价（要认）

链式工作流意味着**没有兜底**。Graphiti 那个事故能发生，就是因为链上某一步的判断没人拦。所以链上每个 LLM 调用点都要有**确定性校验兜着**——Q45 的三段式（规划 → 校验 → 落盘）已经是这个形状，继续按它走。

### 三条不变的底线

这三个是 Q51 立的，新架构不能碰：

1. **流程日志和运行日志绝不进 vault** —— 进去就成了笔记，会被检索、被当知识。技术日志是噪音。
2. **`用户的判断` 机械清空** —— 不靠提示词，靠落盘时强制清空。
3. **审核只审规则，不审内容** —— 「内容该不该这么归类」是整理的事。审核只管「名字和路径合不合规则」。

## 四、阶段划分

### 阶段一：结构定型

**目标：在新结构下能日常用起来。**

- 摊平目录（`10_项目/<项目名>/`）
- 命名规则落地（`命名规则.md` 变成代码里的常量与校验）
- 第二层具备修改能力（`--revise` + 标记失效）
- **闭环重跑** —— 现有 4 篇笔记直落 `20_知识/`，从没走过「进项目 → 抽离可复用知识」这条路。**这条路径没验过，就不算跑通**
- **Web UI 界面设计**（与上述并行，只做界面不做功能）

**验收：** 拿一个真实项目走完整条路——建库、投递、整理进项目、抽出可复用知识、`--revise` 改一条结论；改完旧结论还在且标着失效、不进检索结果。**重跑出来的库替换掉现有那 4 篇。**

### 阶段二：分类能长 + 可观测

**目标：边用边长跑通，且出问题能查。**

- 审核调用点（按规则审，不按内容审）
- 新建分类前先对比现有分类
- 建目录申请路径
- 三层日志：整理日志进 vault，流程日志和运行日志落在服务侧的存储目录

**验收：** 整理时遇到库里没有的分类，能走完「申请 → 审核 → 建立」；每一次流转都能在流程日志里查到。

### 阶段三：检索

**目标：会话层 AI 能代查。**

- 检索接口（会话层发关键词或描述，拿回文档）
- 具体方案待定 —— **先量一下库有多大再选技术**

### 阶段四：Web UI 功能

**目标：不开会话也能随手记、能看日志。**

> **界面的设计在阶段一就做（走设计稿），这里只做功能实现。**

- 可折叠左侧栏：`[ai对话] [整理日志] [工作日志] [运行日志]`
- ai对话：借鉴 DeepSeek 布局，会话历史挪到右边
- 整理日志 / 工作日志：长条卡片流，右侧栏手机聊天式逐条发送
- 运行日志：终端样式，原样输出
- 配色白 + 蓝，整理日志卡片淡蓝、工作日志淡粉

### 阶段五：可移植打包

**目标：换机器 / 给别人用，解压即用。** 具体形态取决于待解决问题 H。
