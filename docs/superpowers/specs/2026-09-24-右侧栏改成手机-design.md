# 右侧栏改成手机 设计

**来源**：用户 2026-09-24 的需求，配两张草图（`00.png`，按惯例看完即删）。
可视化原型在 `.superpowers/brainstorm/756-1790215120/content/`（**不入库**）。

## 一、这份文档解决什么

四个页面（整理日志 / 工作日志 / 运行日志 / ai对话）的右侧栏，各自是一套不同的东西：
两个页面是「两个 tab」、一个页面只有一个「箱子」、还有一个是按钮加列表。
用户要把它们**统一换成一台手机**的样子：顶部时间、两个应用、底部 `home`。

## 二、定案清单

| # | 定案 | 出处 / 理由 |
|---|---|---|
| 1 | **四个页面全换** | 用户原话「全部替换」 |
| 2 | **抽屉式**：平时收在右边，留一条细把手，点一下才滑出来 | 用户选了 B。好处是**正文放开到满宽**（现在那条常驻栏占 250px） |
| 3 | **把手钉在抽屉左边缘、跟着抽屉走** | 原型里第一版把把手钉死在屏幕右边，抽屉一出来就把它盖住、点不着收不回去。**那是原型的 bug**，真做不能这样 |
| 4 | **手机滑出来时把桌宠顶开**，同一层级、有碰撞体积 | 用户原话。**不是盖住、也不是穿过**——滑出来时把桌宠推开，手机收回去后桌宠**留在被推到的地方**（不弹回，否则一开一关来回抽） |
| 5 | **颜色一个都不写死，全走变量** | 用户点名要「跟着皮肤变」。`style.css` 本来就有「变量块之外不许出现十六进制」的防回潮测试守着 |
| 6 | **两个应用 = 该页第一个面板 + 历史** | 现在整理日志是「报告/历史」、工作日志是「流程图/历史」，**一对一**搬进手机 |
| 7 | **运行日志只有一个应用**（箱子） | 那个页面本来就只有箱子一样东西。用户答「行」 |
| 8 | **ai对话的两个应用 = 会话历史 + 新会话** | 用户答「放你说的那几个」 |
| 9 | **点进应用之后原样搬进去**，不重写内容 | 用户答「可以」 |
| 10 | **手机里的整理报告气泡**改成矩形 + 左下角小尖 | 用户第二张草图。近直角（不是现在的大圆角），底线在尾巴处**断开** |
| 11 | **只在手机里改**——主区那串对话气泡（`chat.html` 的 `.bubble`）一个字不动 | 用户 2026-09-24：「只在手机里」 |
| 12 | 小尖位置**写死**，不跟着任何东西走 | 用户：「那个小尖是**模仿聊天的气泡框**」——它是个**样式**，不是指示器 |

> ⚠️ **给下一个人：第 10–12 条第一版全写错了。** 我把它当成了**桌宠那个状态气泡**
> （`.pet-bubble`），还画了两屏「尖指着空气」的分析。**那两样是同一个词指的两个东西**：
> 桌宠的状态气泡是 `.pet-bubble`，消息气泡是 `.bubble`，各有各的规则。
> 用户当时答的是「点进应用之后原样搬进去」那条，所以「气泡框」从一开始就指**手机里的消息气泡**。
> 桌宠的 `.pet-bubble` **本次一个字都不改**。

## 三、每个页面装什么

| 页面 | 应用 1 | 应用 2 | 内容来源（原样） |
|---|---|---|---|
| 整理日志 `journal.html` | 报告 | 历史 | 现有 `report` / `history` 两个 pane |
| 工作日志 `flow.html` | 流程图 | 历史 | 现有 `chart` / `history` 两个 pane |
| 运行日志 `runtime.html` | 箱子 | —（只有一个） | `_boxes.html` |
| ai对话 `chat.html` | 会话历史 | 新会话 | 会话列表 / 「开始新会话」那个链接 |

⚠️ **「新会话」是个动作，不是内容**：它现在是个 `<?new=1>` 链接，点一下就开新会话。
做成应用图标之后，点它是**执行那个动作**（开新会话），不是「进去看一个面板」。
这是四个页面里唯一一个「应用 = 动作」的地方，记在这儿免得下一个人当 bug 修。

## 四、手机的三个状态

1. **收着**（默认）：看不见手机，右边只有一条把手探出来
2. **主页**：顶部时间、中间两个应用、底部 `home`
3. **应用内**：顶部多一条细栏（`‹` + 应用名，`‹` 和 `home` 一样回主页），下面是那个 pane 的内容

内容长了**在手机里滚**，页面不动。

## 五、几何与层级

- **尺寸**：宽 **250px**（和现在那条常驻栏同宽，搬家时观感不变），`position: fixed`，
  上下各留 14px 边距
- **收起 / 展开**：`transform: translateX(100%)` ↔ `translateX(0)`，缓动 460ms
- **把手**：钉在抽屉**左边缘**（`left: -28px`），宽 28px、高 66px、垂直居中。
  收着时抽屉左边缘正好落在视口右缘，**那 28px 探在外面**——这是它唯一能被点到的位置
- **层级**：**40，和桌宠同一层**（用户原话「他们在同一层级」）。
  正常情况下两者不重叠（碰撞会推开），万一动画中有那么一两帧挨上，
  让 DOM 里**手机排在桌宠前面**，桌宠画在上面
- ⚠️ **别给任何祖先加 `transform` / `filter` / `will-change` / `contain`**。
  桌宠那套坐标（`offsetLeft/offsetTop` 相对视口）靠的就是 `offsetParent` 为 `null`，
  加了就整体偏掉而且**页面不报任何错**。手机自己是 `fixed`，不受影响，
  但它要是被塞进一个带 `transform` 的容器里就完了

## 六、桌宠被推开（这一节要和 `pet.js` 配合）

**判据是「手机左边缘」和「桌宠右边缘」有没有重叠**，重叠多少就推开多少，外加一点空隙。
推开用「弹」的缓动（有点过冲），跟手机滑出来同步。

**两个文件怎么通话**：`phone.js` 在开合时派一个自定义事件，
`pet.js` 监听它——**不让它们互相 import**（那会把两个独立的东西焊死）。事件带上
`{open: bool, leftEdge: number}`，`pet.js` 拿左边缘自己算要被推到哪儿。
这样桌宠那套物理（速度、摩擦、反弹）还是它自己说了算。

## 七、手机里的消息气泡

**只在手机里改。** 用户 2026-09-24：「只在手机里」——`chat.html` 主区那串对话气泡
（`.bubble.user` / `.bubble.assistant`）**一个字不动**。

手机里会出现气泡的地方**只有一处**：**整理日志 → 报告**那个面板
（`journal.html:43` 那个 `{% for r in latest %}` 循环，每个 `div.bubble.assistant`
就是一条整理报告）。另外三个页面的应用里没有气泡：工作日志是流程链、
运行日志是箱子、ai对话是会话列表。

改成草图上那个样子：

- `border-radius` 收到 **3px 左右**（近直角，不是现在那套 12px 的圆角）
- 加一个**朝下的小三角**挂在底部偏左，**描边和填充两个三角叠出来**
  （外面那个用边框色、里面那个用底色）
- ⚠️ **里面那个底色三角要比外面那个高一点**（上沿抬进边框里约 3px），
  把气泡自己那条底边在尾巴处**盖断**——草图里底线在尾巴处是断开的。
  不盖的话会有一条横线从尾巴上穿过去（**原型上实测过，第一版就是这样**）

⚠️ **这个尖是个样式，不是指示器**：它不指任何人、不跟任何东西走，位置写死
（离气泡左边一个固定值）。**别去纠结它指着谁，也别为它加任何定位逻辑。**

### 连带要清的 CSS（⚠️ 有一条是雷）

四处页面一换，`style.css` 里这一族选择器就悬空了：`.chat-history`、
`.chat-history h2`、`.chat-history .thread`、`.chat-history .bubble*`、
`.chat-history .pane .bubble + .bubble`、`.chat-item`、`.new-chat`、
`.tabs` / `.tab` / `.pane`。**该删的删、该改选择器的改选择器**，别留一堆没人用的。

⚠️ **但 `.chat-history .bubble` 那条覆盖不能丢**，它带着一段实测注释：

> **必须覆盖掉全局 `.bubble` 的 `pre-wrap`**：侧栏气泡的内容来自模板，
> 标签前后的换行与缩进会被原样画出来——每个气泡凭空多一行空白。
> （主区对话气泡要靠 `pre-wrap` 保住用户输入的换行，那边不动。）

内容搬进手机之后，这条要**重新找到一个选择器接住**（比如 `.phone-view .bubble`）。
丢了它，症状是**每个气泡都多一行空白**——而那种毛病在截图里不一定看得出来。

同理 `.chat-history .pane .bubble + .bubble { margin-top: 8px }`：它治的是
「模板直接 `{% for %}` 循环出来的气泡一条贴着一条，看着像个被切开的方块」。
搬过去之后相邻气泡还得分开。

## 九、边界与错误处理

- **窄窗口**：手机固定宽 250px，窗口比它窄时……照常滑出来（它 `fixed`，压在内容上）。
  不为此做专门处理
- **`localStorage`**：手机的开合状态**不记**——每次进页面都是收着的（默认态）。
  桌宠的位置照旧记着
- **抽屉开着时切页面**：新页面默认收着
- **应用内容为空**：照旧显示现在那些空状态文案（「还没有整理过。」之类）

## 十、测试

**能自动测的**（`pytest`）：

| 钉什么 | 怎么钉 |
|---|---|
| 四个页面都引了手机、都引了 `phone.js` | 字符串断言（沿用 `test_setup.py` 那批的写法） |
| `phone.js` 真能被取到 | 同上 |
| 手机样式真在 `style.css` 里且是 `position: fixed` | 读文件断言。**这条挡的是本项目唯一那种「页面看着正常、测试全绿、功能其实没了」**——把样式块删掉，前面几条照样绿 |
| 气泡不许写死色值 | **现成的**防回潮测试自动覆盖（它扫整个 `style.css`） |

⚠️ **有三条既有用例会被这次改动撞红。它们是「改」，不是「删」**——
三条守的意图都还成立，只是结构换了。

| 用例（都在 `tests/web/test_router.py`） | 它守什么 | 怎么改 |
|---|---|---|
| `test_journal_sidebar_has_two_tabs`（:228） | 整理日志的右栏是「报告 \| 历史」、默认开报告 | 换成断手机：有 `class="phone"`、两个应用名都在；「默认开哪个」那条**改成断默认在主页**（主页两个应用都摆着，没有「active」这个概念了） |
| `test_flow_page_has_the_chain_tab`（:408） | 工作日志的右栏是「流程图 \| 历史」，且链画得出来 | 前两条照旧断应用名；**`>投递<` 那条一个字别动**——它守的是流程链真画出来了，跟页签没有半点关系 |
| `test_runtime_page_has_no_tabs`（:424） | 运行日志没有页签容器 | 两条断言**原样留着**（见下） |

**为什么 `class="tabs"` / `data-pane=` 那两条要留着**：那条用例的 docstring 写着
「**断结构，别断内容**」——原先断的是 `"历史" not in r.text`，而运行日志页显示的正是
**本机真实的** `data/logs/kb/`（`LOG_DIR` 是模块常量，测试没隔离它），日志里一旦出现
「历史」两个字就无故变红。**这条教训别丢。**

**所以手机的标记形式定死**（不定死的话，`data-pane=` 那条会莫名其妙变红，
而看的人会以为是自己写错了）：

- 应用格：`<div class="phone-app" data-app="report">`
- 应用内容区：`<div class="phone-view" data-app="report" hidden>`
- **一律不许再出现 `data-pane`**——那个名字是页签时代的

这样 `test_runtime_page_has_no_tabs` 那两条断言一个字都不用改，仍然在守。

**只能人点的**（本项目没有浏览器测试）：
**滑出来的手感、桌宠被推开的时机与力度、气泡小尖画没画对（底线断没断）、六套皮肤下的观感**。
跑起来人点一遍，别拿「测试全绿」去担保这几件它根本没管的事。
