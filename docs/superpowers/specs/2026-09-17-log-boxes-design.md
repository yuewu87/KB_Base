# 日志箱子与巡检页 设计

**日期：** 2026-09-17
**状态：** 待用户过目

---

## 一、这份文档解决什么

三件事，它们是同一个动作的三个面：

1. **三个日志页没有「往回翻」的入口。** 主区把**所有天**铺成一长条——今天 16 条笔记、明天 30 条，翻昨天的记录要滚很久。右侧栏要么是没用的气泡列表（整理日志页），要么是流程图跟巡检报告挤在一起（工作日志页）。
2. **巡检报告没地方待。** 它现在挤在工作日志页的侧栏里，底下挂着两个按钮。它和工作日志是两件事——一个是「服务建议你改什么」，一个是「服务做了什么」。
3. **「整理日志与流程日志是一页还是两页」这个悬案**（[`02_需求.md`](../../02_需求.md) 的布局设想写两页、Q50 的注释写同一页、实现是两页）。本次一并结掉。

**顺带修一个存储问题：** 流程日志（`flow.jsonl`）和运行日志（`kb.log`）都是**一个文件混着所有天**，且运行日志按**大小**轮转——一天写多了会被切成 `kb.log.1`，跟日期对不上。

## 二、定案清单

| # | 定案 | 理由 / 出处 |
|---|---|---|
| 1 | **三个日志页保留**，各自独立 | Q80 的分界是「是不是知识」——整理日志进 vault，流程/运行日志留服务侧。同一条分界继续管着它们 |
| 2 | **每个页面有自己的一列箱子**，箱子 = 那一天 | 用户 2026-09-17 选 A（不共用托盘） |
| 3 | **箱子按天落盘**；那天没产生日志就不建箱子 | 用户 2026-09-17 |
| 4 | **`26_9_17箱子` 只是界面叫法**，落盘沿用各自既有命名 | 用户 2026-09-17 选 A。整理日志是 vault 里的笔记，文件名跟标题一致是现有约定，改名对 Obsidian 的 `[[链接]]` 不友好 |
| 5 | **右侧栏两个竖排页签**（贴着侧栏左边缘、竖排文字、点哪个哪个高亮），内容跟着页面走 | 见下表 |
| 6 | **「报告」「流程图」页签固定显示最近一次**，**与箱子无关** | 用户 2026-09-17 选 B |
| 7 | **巡检单开一页**，与 ai对话、三个日志并列 | 用户 2026-09-17 |
| 8 | **运行日志自己写按天 handler**，不用 `TimedRotatingFileHandler` | 用户 2026-09-17 选方案一。标准库那个靠**文件 mtime** 判断轮转，服务重启跨天时会把昨天的内容写进今天的文件 |

### 页签表

| 页面 | 竖排页签 | 页签里是什么 |
|---|---|---|
| 整理日志 | **报告** \| **历史** | 报告 = 最近一次整理的文字记录；历史 = 箱子列表 |
| 工作日志 | **流程图** \| **历史** | 流程图 = 最近一次操作的六个步骤（✓/○ 竖排）；历史 = 箱子列表 |
| 运行日志 | **无页签** | 只有箱子列表，直接在右侧栏 |

**默认开哪个页签：** 「报告 / 流程图」（最近一次）。理由是那是你点进这一页最常想看的东西；箱子点一下就到。

### ⚠️ 一处要你确认：「报告」的内容从哪来

**这是我替你定的，看了不同意就说。**

「报告」「流程图」**同源**——都取**最近一次 run 的流程记录**，只是渲染方式不同：流程图把那六个步骤画成 ✓/○ 竖排，报告把那几条文字（「模型决定放进「计算机/git」」「落盘：新建 xxx.md」）原样列出来。

**为什么这么定，而不是新存一份「整理报告」：**

- 那份数据本来就在流程日志里，**不用新增持久化状态**——多存一份就有两份可能对不上的副本，正是 Q50 那句「报告说新建 3 篇、日志写 4 篇」的成因
- 现在返回给会话的那句「已归到 计算机/Python/xxx」，是**当场拼的字符串，没有落盘**。要单独存它就得新加一处状态

**代价（说清楚）：** 流程图和报告会是同一次 run 的两种看法，不是两个独立的东西。如果你要的「报告」是别的来源（比如某天整理完的汇总、或者别的措辞），告诉我，这条我改。

## 三、数据落盘

| 日志 | 现在 | 改成 | 谁写 | 进 vault |
|---|---|---|---|---|
| **整理日志** | `_索引/整理日志/2026-09-17.md` | **不变** | 服务 | ✅ |
| **流程日志** | `data/logs/flow.jsonl` | `data/logs/flow/2026-09-17.jsonl` | `flow.emit` | ❌ |
| **运行日志** | `data/logs/kb.log`（按大小轮转） | `data/logs/kb/2026-09-17.log` | 新的按天 handler | ❌ |

- **日期取写入时刻的本地日期**（`datetime.now()`），不是记录里的字段——写入和落点必须是同一个判断，否则跨午夜那一秒会写串。
- **整理日志天然满足**：它本来就是一天一个文件，一行代码不用改。

### 运行日志的按天 handler

`logging_setup.py` 现在用 `RotatingFileHandler(maxBytes, backupCount)`。改成一个自定义 `Handler`：

- `emit()` 时算当天日期，取 `data/logs/kb/YYYY-MM-DD.log`，**文件句柄按日期缓存**——同一天里不能每条日志都开关一次文件
- 日期变了就换句柄
- **`handleError` 不能拖垮服务**：写失败（磁盘满、权限）只吞掉，不能往上抛——日志是附属品

### 保留策略

- **服务侧日志保留 90 天**（流程 + 运行），服务启动时删掉更早的**按天文件**。常量可改。
- **vault 里的整理日志永不自动删**——它是知识，不是日志。

### 一次性迁移

现有两个文件都要拆进新结构（都是小文件，一次做完）：

| 文件 | 现状 | 怎么迁 |
|---|---|---|
| `data/logs/flow.jsonl` | 640 条，**全是 2026-09-17** | 整份移到 `data/logs/flow/2026-09-17.jsonl` |
| `data/logs/kb.log` | 65 行，10 行是 09-16、55 行是 09-17 | 按行首时间戳拆进 `kb/2026-09-16.log` 与 `kb/2026-09-17.log` |

**写成一次性脚本（`scripts/migrate_logs.py`），跑完即弃**，不留常驻逻辑——旧格式只出现这一次。迁完确认内容对得上再删旧文件。

## 四、页面结构

三个日志页共用一套骨架：

```
[左侧主导航]  [主区 · 只看选中的那一天]  [页签 | 右侧栏]
```

- **主区**：选中那天的那一类日志（沿用现在的卡片样式与配色）
- **右侧栏**：两个竖排页签贴在左边缘（形如 `00.png`），点页签换内容
- **箱子按钮**：样式复用现在的「会话按钮」（`.chat-item`），点它 = 换 `?d=` 参数

### 左侧导航（六项）

```
＋ 记一条
ai对话
—————
整理日志
工作日志
运行日志
—————
巡检
```

**原来左栏那个「巡检一次」按钮挪进巡检页**——它是那个页面自己的动作，不该挂在全局导航上。

### 巡检页

```
巡检报告（金框，就是现在工作日志侧栏里那块）
  └ [我知道了] [还需调整]
[巡检一次]
上次巡检：9 月 17 日 09:12（超过 6 天服务启动时自动跑）
```

没有右侧栏。报告读完（`read: true`）后仍然显示，只是不再高亮——**这一页就是它的家**，跟原来「没读才冒出来」的侧栏逻辑不同。

## 五、路由与参数

| 路由 | 页面 | 主区 | 右侧栏 |
|---|---|---|---|
| `/` | ai对话 | 对话 | 会话历史（**不变**） |
| `/new` | 记一条 | 表单 | 无 |
| `/journal?d=YYYY-MM-DD` | 整理日志 | 该日整理日志 | 报告 \| 历史 |
| `/flow?d=YYYY-MM-DD` | 工作日志 | 该日流程记录 | 流程图 \| 历史 |
| `/runtime?d=YYYY-MM-DD` | 运行日志 | 该日终端输出 | 箱子 |
| `/sweep` | 巡检 | 报告 + 按钮 | 无 |

- **`d` 省略 → 最新一个有箱子的日子**（不是「今天」——今天可能还没产生日志，那样进页面是空的）
- 一个箱子都没有 → 主区空态，文案说明怎么产生第一条
- 箱子列表**倒序**（新的在上）
- `/sweep/run` 跑完**重定向回 `/sweep`**（现在重定向到 `/flow`）

## 七、边界与错误处理

| 情况 | 怎么处理 |
|---|---|
| `?d=` 指向没有日志的日子 | 主区空态，**不 404**——用户手改 URL 或书签过期都不该看到错误页 |
| `?d=` 格式非法（`2026-13-99`） | 同上，当「没有这一天」处理 |
| 日志目录不存在 | 空列表（沿用 `read_flow` 现有约定） |
| 写流程日志失败 | 吞掉（`flow.emit` 现有约定：日志是附属品，不该拖垮整理） |
| 写运行日志失败 | 吞掉（handler 的 `handleError`） |
| 跨午夜写入 | 按**写入时刻**选文件，不做「这次整理从头到尾用同一个日期」的特殊处理——一次整理跨午夜的概率极低，不值得为它加状态 |

## 八、测试

- **按天落盘**：给定 `now`，`emit` 写进 `flow/YYYY-MM-DD.jsonl`（用 `monkeypatch` 控时间）
- **跨天切换**：同一天两次 emit 只开一次文件；换天后换文件
- **运行日志 handler**：同一天不重复开关；换天换文件；写失败不抛
- **`list_days`**：倒序、只列真实存在的天、空目录返回空
- **`read_day`**：只返回那天的；不存在的天返回空（不抛）
- **路由**：`?d=` 省略落在最新一天；非法 `d` 走空态不 404；`/sweep` 200
- **页签与箱子**：三个页面各自的页签集合正确（运行日志页没有页签）
- **迁移脚本**：拿两份真格式的样本文件，拆完两边内容合起来等于原文
