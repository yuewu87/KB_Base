# ai对话实时显示过程（流式）

**日期**：2026-10-08
**由来**：Q116 记的「转圈没进度」——用户发一条列了十几个条目的消息，界面转圈 29 秒
什么都没动（库其实在涨），最后只收到一句「我转的圈数太多了」。用户要求**实时看到它在干什么**。

---

## 决定（用户拍的）

| 问题 | 选择 |
|---|---|
| 要看到什么 | **动作 + 模型说的话**（不含模型的原始推理 `reasoning_content`） |
| 显示成什么样 | **每个动作一条独立气泡**，跑完保留 |
| 刷新后还在吗 | **存进会话历史** |
| 粒度 | 只到**动作层**（「正在投递…」→「投好了」），**不显示整理链内部** |
| 传输方式 | **NDJSON**（每行一个 JSON），不用 SSE |

---

## 事件流

`core/chat.py` 的 `run_turn` 改成**生成器**，边跑边 yield 事件：

```json
{"type": "say",    "text": "好，我这就去存"}
{"type": "action", "text": "正在投递：MCP 模型上下文协议", "name": "push"}
{"type": "result", "text": "投好了 → 计算机/LLM 自动化/MCP 模型上下文协议.md"}
{"type": "done",   "chat_id": "20261008-ab12"}
{"type": "error",  "text": "模型超时了"}
```

- `say` —— 每轮模型说的话（现在算了但丢掉）
- `action` —— 动作开始前
- `result` —— 动作返回的结果文本（`run_action` 本来就返回给人看的文本）
- `done` —— 收尾，带会话 id（前端用它更新 URL / 侧栏）
- `error` —— 出错（含 `MAX_ROUNDS` 撞顶那句）

**不新增事件类型**：动作内部的整理链（规划/校验/落盘/commit）不往外推——
那些已经在写流程日志（`flow.emit`）了，要看去「工作日志」页。

---

## 分层

| 文件 | 改什么 |
|---|---|
| `src/kb/core/chat.py` | `run_turn` → 生成器（逐事件 yield）；**`handle` 保留**——它消费生成器、跑完返回。`POST /chat`（CLI / 会话层用的 JSON 端点）行为不变 |
| `src/kb/web/router.py` | 新增流式端点；`chat_post` 改走它 |
| `src/kb/web/templates/chat.html` | 整页 POST → `fetch` + 读流 + 逐条追加气泡 |
| `src/kb/core/chat_store.py` | 落盘时**保留 `tool` 轮**（现在只留 user + 最终 assistant） |

### 渲染上的现成便宜

`chat.html:35` 现在是 `{% if m.role != "tool" %}` —— **tool 轮早就有位置，只是被排除了**。
去掉那个排除、把内容格式改成给人看的，就出来了。

而且因为存进了历史，**下一轮模型也能看到**——这顺带修掉 Q116 记的
「跨对话轮健忘、可能重复存」。所以 `tool` 轮的内容要**两边都能用**：

```
投递：MCP 模型上下文协议 → 已存入 计算机/LLM 自动化/MCP 模型上下文协议.md
```

（`_render_history` 会给它加「工具结果」前缀给模型看；前端直接渲染正文。）

## 错误处理

Q104 当初选整页 POST 的理由之一是「网络断了时浏览器自带的错误页更说得清」。
改流式后这条要自己管，两个入口：

- 流里推 `{"type": "error", "text": ...}` → 前端画一条**红色气泡**
- 网络直接断 → `fetch` 的 `catch` → 画「连接断了，刷新重试」

**不许白屏，也不许停在「思考中…」。**
