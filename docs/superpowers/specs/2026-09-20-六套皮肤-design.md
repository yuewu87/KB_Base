# 六套皮肤 + 切换入口

2026-09-20 · 设计文档（brainstorming 产出）· 状态：待过目

---

## 一、背景与目标

Web UI 目前只有一套配色（去饱和藏蓝），硬编码在 `src/kb/web/static/style.css` 的
`:root` 以及另外 40 处散落的十六进制里。

用户提供了四组撞色参考，要求做成可选皮肤：**布局结构一行不动，只有颜色变**。
加上「保留现有蓝」和「现有皮肤白换黑」，一共六套。

**做成什么样算完成：**

1. 六套皮肤都能用，切换后**整站**（六个页面 + 设置窗 + 遮罩层）都是对的颜色，没有漏网的蓝色。
2. 左栏底部一个入口能切，**点一下当场变**，不刷新、不重启服务。
3. 选过之后记住，下次打开还是那套。
4. 不选的时候，就是今天这套蓝——**一字不差**。

## 二、非目标

- **绝区零风格的元素/排版处理，不在这轮。** 用户已明确分成两轮，这轮只做配色与切换。
  下一轮单独做（任务 #80）。
- **不动布局。** 不改栅格、间距、字号、圆角、动效时长。`--r-*` / `--dur` / `--ease` /
  `--sidebar*` / `--reading` 保持为全局常量，不进皮肤。
- **不做「跟随系统深色模式」。** 深色皮是手动选的，不是 `prefers-color-scheme` 自动切的。
- **不做每套皮肤各自的字体。** 全站系统栈不变（离线工具，不引外链字体）。

## 三、技术方案

`<html>` 上写 `data-skin`，CSS 里按属性重定义变量。

```html
<html lang="zh-CN" data-skin="{{ skin }}">
```

```css
:root                      { /* ⑤ 现有蓝：默认值 */ }
[data-skin="dark-pink"]    { /* ① */ }
[data-skin="aurora"]       { /* ② */ }
[data-skin="garnet"]       { /* ③ */ }
[data-skin="neon"]         { /* ④ */ }
[data-skin="mono"]         { /* ⑥ */ }
```

**为什么是这套**（备选是「每套皮肤一个 `<link>`，切换时换 href」）：

| | `data-skin` + 变量 | 每套一个 `<link>` |
|---|---|---|
| 首屏 | 服务端渲染就是对的颜色，**无闪烁** | 要等 CSS 到了才知道，会闪一下旧色 |
| 请求 | 零额外请求 | 切一次加载一个文件 |
| 深色皮 | 能顺带设 `color-scheme: dark`（滚动条、表单控件跟着变） | 同样能做，但要多一套加载时序 |
| 不写属性 | 回落 `:root` = 现有蓝，正好是想要的行为 | 要多写一个默认文件 |
| 改一处值 | 改一处 | 六处 |

`color-scheme` 那条是决定性的：深色皮里，滚动条、`<select>` 下拉、`<input readonly>`
这些**浏览器原生画的东西**只有认了 `color-scheme: dark` 才会跟着变暗。否则四套深色皮
会在边上漏出一圈白。

**浏览器门槛**：属性选择器、CSS 自定义属性、`color-scheme` 三样分别要 Chrome 49 / 49 / 81
（2016–2020 年就有）。本项目现有的 `style.css` **没有用任何比这更新的东西**
（无 `@scope`、无 `color-mix()`、无 `@supports`），所以这个方案**不提高门槛**。

> 顺带一提：impeccable 的 live 模式会往页面注入 `@scope`，那是它自己的东西，不是本项目的，
> 已经清干净了。别把它当成现有的兼容性下限。

## 四、变量层

### 4.1 改名

现有的 `--blue*` / `--pink*` 是「按颜色命名」，一旦换皮就是谎话（粉色皮肤里
`--blue-soft` 底是粉的）。改成按**角色**命名：

| 旧名 | 新名 | 角色 |
|---|---|---|
| `--blue` | `--accent` | 强调色：主按钮底、链接、选中的字 |
| `--blue-mid` | `--accent-mid` | 强调色亮一档：hover、焦点环 |
| `--blue-soft` | `--accent-soft` | 强调色洗底：选中项底、用户气泡底 |
| `--blue-tint` | `--accent-tint` | 强调色极淡底：次级按钮底 |
| `--pink-soft` | `--journal-soft` | 工作日志卡片底 |
| `--pink-line` | `--journal-line` | 工作日志卡片边框 |

`--accent-soft`），推导 26 个。

### 4.3 `--accent-ink`：强调色当文字用时的那一档

**这是推导过程中发现的问题，不是原设计的一部分。**

强调色有两个用途，对对比度的要求不一样：

- **当填充**（按钮底、标签底）——只要上面的字看得清就行，色相可以很浅。
- **当文字**（链接、选中的导航项、`.chat-item.active .chat-title`）——**它自己要 4.5:1**。

六套锚点里有两套的强调色当文字**读不清**：

| 皮肤 | 强调色 | 压在自己的底上 |
|---|---|---|
| ② 极光紫 | `#9F82FD` | **2.85:1** |
| ⑥ 黑皮 | `#2F5D8A` | **2.60:1** |
| ① 甜酷粉 | `#E6397C` | 4.33:1（擦边） |

修法：**不动用户定的六个锚点**，而是多出一档 `--accent-ink`——「强调色用来写字时」
的版本，由代码把它朝可读方向推到达标：

- 浅色皮：往 `--ink` 方向推，直到对 `--paper` ≥ 4.5:1
- 深色皮：往 `#ffffff` 推，同样到 4.5:1

② 推出 `#7b65c3`，⑥ 推出 `#6083a5`，① 推出 `#e74081`。**填充仍然用原锚点**，
所以调色板的样子没变，只是「当字用」的时候自动换一档。

### 4.4 推导规则（可复现）

其余 25 个值全部由锚点按固定比例算出，**不含手调**（第 26 个 `--accent-ink` 见 4.3）：

```
--muted        = mix(ink, paper, 0.29)          # 比例由 ⑤ 反推
--faint        = mix(ink, paper, 0.50)
--ink-soft     = mix(ink, paper, 0.16)
--faint-dim    = mix(ink, paper, 0.62)
--line-soft    = mix(line, surface, 0.45)
--line-strong  = mix(line, ink, 0.12)
--accent-mid   = mix(accent, #fff, 0.22 深 / 0.14 浅)
--accent-tint  = mix(accent, paper, 0.98)
--accent-line  = mix(accent-soft, accent, 0.10)
--accent-ring  = rgba(accent-mid, .28 深 / .12 浅)
--divider      = mix(surface, ink, 0.22)        # 侧栏那根深色分隔线
--on-accent    = pick_ink(accent)               # 白字 ≥4.5 就用白，否则用黑
--on-danger    = pick_ink(danger)

深色皮：
  --shadow/--shadow-lift  纯黑 .40/.32 与 .48/.42
  --scrim                 rgba(0,0,0,.62)
  --terminal-void         = mix(paper, #000, 0.45)
  --terminal-text         = mix(muted, #fff, 0.55)
  --journal-soft          = mix(surface, accent, 0.14)
  --journal-line          = mix(surface, accent, 0.42)
  --danger #d4736f  --danger-hover #e08a86

浅色皮：
  --shadow/--shadow-lift  rgba(ink, .04/.045) 与 (.07/.07)
  --scrim                 = rgba(ink, .38)
  --terminal-void         = mix(ink, #000, 0.22)
  --terminal-text         = mix(ink, #fff, 0.78)
  --journal-soft          = mix(accent, surface, 0.92)
  --journal-line          = mix(accent, surface, 0.72)
  --danger #8c3b3b  --danger-hover #a24646

巡检金（第二色优先）：
  ② 取蜜柚黄 #FBEA03      ④ 取极光紫 #9F82FD
  ①⑥ 取 accent            ③ 取 mix(accent, #c9a86a, .5)
  --sweep-gold-deep = 深色往白提 .12 / 浅色往黑压 .16
  --sweep-gold-wash = mix(gold, surface, .86 深 / .90 浅)

mix(a, b, t) = a 向 b 线性插值 t（在 gamma 编码的 sRGB 上，与 CSS color-mix 一致）
```

**⑤ 不参与推导**，6 个锚点 + 26 个推导值全部硬编码成今天线上生效的值
（见 8.1 的合并说明）。用户要求「原样保留」。

`scripts/derive_skins.py` 落地这套规则，输出 `.skin-*.css` 片段；
**测试断言「style.css 里的皮肤块 == 脚本输出」**，防止手改漂移。

## 六、切换入口与持久化

### 6.1 配置项

`KB_SKIN`，`kind="choice"`，六个取值 `archive` / `dark-pink` / `aurora` / `garnet` /
`neon` / `mono`，默认 `archive`。

落在 `settings.GROUPS` 新增的一组「外观」里。**入口虽然不在设置窗里，配置项仍然进设置窗**
——设置窗是「所有能改的配置」的清单，皮肤藏在别处会让人找不到。

链路（复用现有的，不新开）：左栏小面板 → `POST /settings` → `apply_settings` →
写 `.env` → `reload_config` → 换进 `state["cfg"]` → 下个请求 `get_cfg()` 读新的。
**全程不用重启服务**，`get_cfg()` 是每请求现读的。

`config.py` 里按 `_log_level` 的既有写法加一个 `_skin(values)`：认不出的一律回落
`archive`——手改 `.env` 写错值不能让服务 500，这和 `_log_level` 是同一条理由。

### 6.2 入口长什么样

左栏底部，「退出」上面，加一项「外观」（复用 `.side-btn`，图标用调色盘）。点开是一个
**小面板**：六行，每行 = 色点 + 皮肤名 + 当前项打勾。点一行就切。

- **面板是浮层**，锚在按钮右边，不受侧栏宽度限制。折叠成 60px 时侧栏只剩图标，**面板照样能开**
  ——这是「放左栏底部」和「折叠态」的冲突点，浮层是解。
- 点面板外面关掉；`Esc` 也关。
- 键盘可达（`aria-haspopup` / `aria-expanded` / 方向键）。

### 6.3 切换的瞬间

```js
document.documentElement.dataset.skin = id;   // 当场变，零延迟、不刷新
fetch('/settings', {method:'POST', ...});      // 后台落盘
```

**先改 DOM 再发请求**：DOM 改了立刻见效，请求失败也只影响「下次打开是不是这套」，
不会让界面卡一下。失败了给一句提示（复用 `_msg`），不静默吞掉——和 `saveSettings`
里 `catch` 那条的理由一样。

## 七、测试

1. **变量齐全**：参数化六套皮肤，断言每套的 32 个变量都有值，且都是合法的颜色字面量。
2. **不写属性 = ⑤**：`get_skin()` 对空值、未知值、非法值都返回 `archive`。
3. **`KB_SKIN` 非法值被挡**：`settings.validate({"KB_SKIN": "purple"})` 抛 `SettingsError`；
   合法值写进 `.env` 后 `read_env` 能读回来。
4. **页面带对了属性**：渲染 `/`、`/journal`、`/flow`、`/runtime`、`/sweep`、`/new`
   六个页面，断言 `<html ... data-skin="...">` 与当前配置一致。
5. **没有漏网的硬编码**：扫 `style.css`，断言 `:root` 与皮肤块之外**不出现十六进制色值**。
   —— 这条是防回潮的，比逐条比对更能挡住「下次又写死一个」。
6. **推导可复现**：`scripts/derive_skins.py` 的输出与 `style.css` 里的皮肤块逐字相等。

## 八、已知取舍与风险

### 8.1 ⑤ 的「原样」有合并，会动 4 条边框规则（**需要拍板**）

要把 40 处写死值收进变量层，就得给「边框的强弱」定语义档位。⑤ 目前有 **5 个手挑的
近色**在干同一件事：

| 位置 | 现在的值 |
|---|---|
| `.side-action` / `button.secondary` 边框 | `#cfdeee` |
| `.card:hover` / `.card.sweep.read:hover` 边框 | `#d3dce7` |
| `.tab.active` 边框 | `#b9c6d6` |
| `.tag` 边框 | `#dae6f3` |
| `.card.journal` / `.bubble.user` / `.new-chat:hover` 边框 | `#dbe7f4` |

合并成两档（`--line-strong` = `#d3dce7`，`--accent-line` = `#dbe7f4`）之后，
**⑤ 会有 4 条规则、共 5 个选择器的 1px 边框动 1-2 个色阶**：

- `.side-action`、`button.secondary`：`#cfdeee` → `#d3dce7`（略深）
- `.tag`：`#dae6f3` → `#dbe7f4`（几乎无差）
- **`.tab.active`：`#b9c6d6` → `#d3dce7`（变淡）** ← 这条最可能看出来

另外 `.settings-msg.bad` 的错字颜色 `#a33` → `--danger` `#8c3b3b`（略深）。

**取舍**：(a) 统一，⑤ 有上面这几处微调；(b) 严格原样，变量层多三个「只为一处服务」的
变量。**推荐 (a)**——5 个近色本来就是这个文件反复踩「两处真相」坑的产物，正是变量层该
收拾的东西；而且差异都在 1px 边框上。

如果 `.tab.active` 那根边框变淡不能接受，退路是给它单独留一个 `--tab-line`，
代价是变量层多一个只服务一处的名字。

### 8.2 ①②③④ 的按钮文字会变成黑色（**需要拍板**）

`--on-accent` 的规则是「白字达标（≥4.5:1）就用白，否则用黑」。粉、紫、红、荧光绿
四种填充色上白字都不达标，所以这四套的「发送」「搜索」「选中的标签」会变成黑字：

| 皮肤 | 强调色对底 | 白字 | 黑字 | 选中 |
|---|---|---|---|---|
| ① `#E6397C` | 甜酷粉 | 4.01 | **4.94** | 黑 |
| ② `#9F82FD` | 极光紫 | 2.96 | **6.67** | 黑 |
| ③ `#E72D48` | 石榴红 | 4.32 | **4.58** | 黑 |
| ④ `#BCFE1A` | 荧光绿 | 1.21 | **16.32** | 黑 |
| ⑤ `#2F5D8A` | 现有蓝 | **6.88** | 2.88 | 白（不变） |
| ⑥ `#2F5D8A` | 现有蓝 | **6.88** | 2.88 | 白（不变） |

①③ 是擦边的两个（③ 白 4.32 / 黑 4.58，只差 0.26）。**如果觉得「白字压红底」的观感
更重要**，说一声，我改成一律白字——代价是 ①③ 停在 4.0-4.3（略欠 4.5），②④ 则基本
看不清。**推荐保持自动**。

### 8.3 ③ 的粉桃当卡底之后，「选中态」会不明显

③ 的 `--journal-soft` 直接用 `#F1DDDF`（粉桃原色，用户 mockup 里的原意），
而 `--accent-soft` 是 `#FBE4E7`——两者很接近。工作日志卡片和选中项如果用同一个底，
会分不出来。实现时会实测一眼，真要撞了就微调 `--accent-soft`。

### 8.4 不做的事

- 不做皮肤预览缩略图（点一下当场全站变色，比缩略图直观）
- 不做「跟随系统」
- 不做导入/导出皮肤
- 不动任何布局数值
