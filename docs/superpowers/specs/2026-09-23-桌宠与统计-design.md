# 对话统计 + 悬浮桌宠 设计

**来源**：用户 2026-09-23 提的两个需求，走完 brainstorming 定案。可视化原型在
`.superpowers/brainstorm/1440-1790210541/content/pet-prototype-2.html`（不入库）。

## 一、这份文档解决什么

**① 对话答不出「有多少」。** 用户原话：「刚才问它一共有多少条内容了，他无法回答，
待整理有多少条也无法回答」。查下来是**它手上没有这个数**——它能做的动作只有
`search` / `push` / `revise` / `organize`，没有「数一数」这一条。

**② 一个悬浮桌宠。** 用户原话：「用左上角的 kb 图标作为形象，跟随皮肤更改颜色，
点击时有果冻效果，还会显示一个气泡框，气泡框显示目前知识库的状态……如果检测到
鼠标快速拖动它时就会弹射出去，在窗口中反弹」。

## 二、定案清单

| # | 定案 | 理由 / 出处 |
|---|---|---|
| 1 | **统计走「每轮直接告诉模型」，不加动作** | 用户 2026-09-23 选 A。问就答、**不额外花一轮**；数字每轮现算所以永远新鲜。代价只是系统提示里多两个整数 |
| 2 | **桌宠全站每一页都在** | 用户 2026-09-23 选 A。它是「常驻小伙伴」，换页还在原位（位置自己记）。拖动就能挪开，所以**不做**额外的「藏起来」开关 |
| 3 | **气泡：点一下弹、几秒后自己收** | 用户 2026-09-23 选 A。约 4 秒淡出，**鼠标停在气泡上就不收**（防正在看时被收走） |
| 4 | **果冻力度用「弹」那档** | 用户在原型里逐个试过之后选的（三档里振幅最大的） |
| 5 | **弹射阈值 2500 px/s** | 用户在原型里拿滑杆调出来的。原型里实时显示「上一次松手：XXX px/s」，他甩了几下定的这个数。**随手拖几百、刻意一甩两三千**——所以 2500 意味着「得刻意快甩」 |
| 6 | **桌宠的 JS 单独放 `static/pet.js`** | 用户 2026-09-23 选 A。它**自成一个东西**（自己的物理循环、持久化状态、气泡），单开一个文件最好找。代价是破了「全仓没有独立 `.js`」这个现状，要在这儿记一笔。**现有那 540 行内联 JS 不动** |
| 7 | **位置记在 `localStorage`，初始右下角** | 用户选「全站每一页」时那句写的就是「位置自己记住」。跨页、跨刷新都在原地 |
| 8 | **拉不到数时如实说，不装作 0** | 「数不出来（原因）」——跟 `/setup/remove` 那条失败路径一个路子（不确定的事不装确定） |
| 9 | **颜色只能走变量，不许写死** | `style.css` 有「变量块之外不许出现十六进制」的防回潮测试守着。这正好也是「跟随皮肤」要的——写死就只在一套皮肤上对 |

## 三、统计：数从哪来、怎么给模型

**数从哪来。** `core/vault.py` 加一处：

```python
def counts(vault_root: Path) -> dict[str, int]:
    """库的规模。**判据只此一份。**"""
    return {"notes": len(list_notes(vault_root)), "drafts": len(list_drafts(vault_root))}
```

`router._counts` 改调它（它另外补 `chats`——那是 `data_dir` 的事，不归 vault）。
放 `core/` 是分层规矩：`router.py` 是薄层，判断全在 core；而对话那次调用也在 core 里，
够不着 web 层。

**怎么给模型。** `core/chat.py` 的 `build_system_prompt()` **现在不收参数**，加一个
`vault_root`：`build_system_prompt(vault_root)`（`run_turn` 手上已经有它）。提示里
多一段：

```
## 当前库

38 篇笔记 · 0 条待整理
```

**没库时**（`vault_root is None`）写「还没有知识库」，**不是**「0 篇笔记」——
后者看着像库坏了，前者才是实话。

**代价。** 每轮多一次目录扫描。38 篇是瞬间；几千篇也就几毫秒（`list_notes` 只走
目录、不读正文）。

## 四、桌宠：结构与交互

**结构。** `base.html` 里加一个 `<div class="pet" id="pet">KB</div>`，**46×46**。
`static/pet.js` 用 `<script src="/static/pet.js" defer>` 引入（新文件）。

**「复用 `.brand-mark`」指的是外观、不是类名。** 颜色（`--accent` 底 + `--on-accent` 字）、
圆角这两样跟左上角那个 KB 标一致；但它还要 `position: fixed`、拖拽光标、果冻动画、
`transform-origin` 这些，`.brand-mark` 里没有，得自己写一套 `.pet` 的规则。

**点击 vs 拖动。** pointer 移动距离 **< 5px** 算点击，否则算拖动：
- 点击 → 果冻 + 气泡
- 拖动 → 跟手走；松手速度 **≥ 2500 px/s** 才弹射，否则**停在原地**（不飞）

**气泡。** 点的时候 `fetch('/setup/state')`（那儿现成有 `counts`），显示：

- 有库：`库里 38 篇笔记 · 待整理 0 条`
- 没库：`还没有知识库`
- 拉失败：`数不出来（原因）`

**4 秒**后淡出；`mouseenter` 暂停计时、`mouseleave` 重新计时。

**位置。** `localStorage`（键 `kn.pet.pos`），值 `{x, y}`（相对**视口**的左上角）。
初始位置是**右下角、离右边缘和下边缘各 24px**。

**气泡贴在桌宠正上方**（离它 8px），**太靠上边或左右边时夹回可视区内**——桌宠被甩到
左上角时气泡不能跑到屏幕外面去。

窗口 `resize` 时把桌宠夹回可视区（不能让窗口一缩小它就飞出屏幕）。

**层级。** 压在 `.overlay`（设置窗 / 各种模态）**下面**——桌宠飘在设置窗上面会挡事。

## 五、物理参数

| 参数 | 值 | 说明 |
|---|---|---|
| 弹射阈值 | **2500 px/s** | 松手速度低于它就不飞（用户在原型里调的） |
| 摩擦 | 0.985 / 帧 | 每帧乘一次，几十帧后停下 |
| 反弹 | 保留 62% | 撞视口边时反向、衰减 |
| 停下阈值 | 0.02 px/ms | 两个方向都低于它就结束动画 |
| 边界 | **视口** | 用户原话「在窗口中反弹」 |

## 七、边界与错误处理

- **没库**：气泡说「还没有知识库」；桌宠照常在、照常能拖能弹
- **`/setup/state` 失败**（服务重启中、网络断）：气泡说「数不出来（原因）」
- **窗口缩到比 46px 还窄**：夹回可视区，可能贴在边上——不额外处理
- **`localStorage` 被禁**（隐私模式）：退回初始右下角，其它功能照常
- **拖动中松开到视口外**：松手时先夹回视口，再算速度

## 八、测试

**能自动测的**（`pytest`）：

| 钉什么 | 怎么钉 |
|---|---|
| `vault.counts` 数得对 | 单测：空库 / 有 N 篇笔记 / 有草稿 |
| 系统提示里带着那两个数 | 跟现有那几条 prompt 测试一个路子 |
| 没库时提示写的是「还没有知识库」 | 同上（防「0 篇」那种看着像坏了的写法） |
| `/setup/state` 的 `counts` 没被改坏 | 现有用例回归 |
| `base.html` 里有 `.pet` 且引了 `pet.js` | 字符串断言（沿用 `test_setup.py` 那批的写法） |
| 桌宠样式不许写死色值 | **现成的**防回潮测试自动覆盖（它扫整个 `style.css`） |

**只能人点的**（本项目没有浏览器测试，跟 Task 7 那批一样）：
**果冻的手感、弹射与反弹、拖动 vs 点击的分界**。跑起来人点一遍，别拿「测试全绿」
去担保这几件它根本没管的事。
