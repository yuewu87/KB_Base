# 设置页与退出按钮 设计

**日期：** 2026-09-17
**状态：** 待用户过目

## 一、这份文档解决什么

**Web UI 没法改配置，也没法关服务。**

配置全在工程根目录的 `.env` 里，改了要手工编辑文件、还要 `kb stop` 让它重启。而「关服务」这件事，双击 `web.bat` 进来的人根本不知道有 `kb stop` 这条命令。

两件都补上：

1. **设置** —— 侧栏一项，点开一个小窗。模型、日志级别、巡检间隔这些当场能改、改完当场生效
2. **退出** —— 侧栏底部一个红按钮，停掉服务

## 二、定案清单

| # | 定案 | 理由 / 出处 |
|---|---|---|
| 1 | 侧栏加**「设置」**，底部加**红色「退出」**，两者之间一条分隔线 | 用户 2026-09-17 |
| 2 | 设置窗是**模态**（遮罩 + 双栏：左列分类、右列内容） | 用户 2026-09-17，布局照 00.png |
| 3 | 窗里**四组**：模型配置 / 知识库 / 服务 / 关于 | 用户指定「里面一个选项是模型配置」，其余我拟、用户已过目 |
| 4 | **保存即生效（热重载）** | 用户 2026-09-17 选 A。换模型是最常改的一项，改完能立刻「测试连接」验 |
| 5 | 退出 = **停服务 → 弹一个提示窗** | 用户 2026-09-17 |

### 一条绕不开的技术限制

**「退出」关不掉标签页。** 浏览器的规矩是 JS 只能关掉**自己打开的**窗口；用户敲地址或点书签进来的标签页，`window.close()` 会被拒。

所以退出只做两件事：**停掉服务**，然后换成一个提示窗——「服务已停。可以关掉这个标签页了。」

（另一条路是让 `web.bat` 用 `--app` 模式开一个专用窗口，那样能关。**不走**：那是另一个窗口不是标签页，用户会困惑。）

## 四、设置窗

模态遮罩 + 双栏。左列四个分类，右列是那一类的内容。

### 模型配置

| 字段 | 键 | 可改 |
|---|---|---|
| 模型名 | `KB_LLM_MODEL` | ✅ |
| API 地址 | `KB_LLM_BASE_URL` | ✅ |
| API Key | `KB_LLM_API_KEY` | ✅ **掩码显示**，留空 = 不改 |
| **[测试连接]** | — | 见下 |

**API Key 不回显原文**，只给 `sk-••••••••3f7a`。留空提交表示「不动它」——这样打开设置窗再原样保存也不会把 key 抹掉。

**[测试连接] 具体做什么**：拿**表单里当前填的值**新建一个 LLM 客户端（不落盘、不改现有的），发一次 `complete("回复 ok 两个字")` 这样的最小请求，报「通了 · 1.2 秒」或「不通：<原因>」。

**它验的是表单里的值，不是已保存的值**——所以「先测试再保存」这条顺序走得通，不用为了测一次就把坏配置先写进 `.env`。

**它要花钱**（一次极小的调用）。这是刻意的：换模型/换 key 时，这是唯一能立刻知道对不对的办法。

### 知识库

| 字段 | 可改 |
|---|---|
| vault 路径 | **只读** |
| 现状（`3 个领域 · 41 篇笔记 · 收件箱 0 条`） | 只读 |

**只读的理由：换库不是常事，换错了整个服务当场废。** 要看就给你看，要改去改 `.env`。

### 服务

| 字段 | 键 | 可改 |
|---|---|---|
| 端口 | `KB_PORT` | **只读** |
| 日志级别 | `KB_LOG_LEVEL` | ✅ INFO / DEBUG |
| 巡检间隔（天） | `KB_SWEEP_INTERVAL` | ✅ 默认 6 |
| 服务侧日志保留（天） | `KB_LOG_KEEP_DAYS` | ✅ 默认 90 |

**端口只读的理由**：改了地址就变，**你收藏的书签就废了**——这是项目踩过的坑（`04_踩坑与经验.md` 第 20 条）。

**后两个现在是硬编码常量**（`sweep_state.SWEEP_INTERVAL` = 6 天、`flow.KEEP_DAYS` / `logging_setup.KEEP_DAYS` = 90 天）。「6 天是拍的」正挂在 `01_架构.md` 第十四节的待办里——搬进来正好把它变成可调的。

### 关于

| 字段 | 说明 |
|---|---|

## 五、保存与生效

```
点保存 → 校验 → 写回 .env → 当场重载 → 反馈
```

### 写 `.env`：**保留注释和顺序**

`.env` 是人手工维护的——里面有解释每一项怎么填的注释。**不能整个文件重写**，那样注释全没了。

做法是逐行扫：命中的键只换值、其余原样抄；文件里没有的键追加到末尾。

### 重载

**不能用 `load_dotenv` 重读**：它是 `override=False` 的，已经设过的环境变量它不覆盖，重载会变成空转。

改用 `dotenv_values(env_file)`——**直接解析文件、返回 dict，不碰 `os.environ`**。

重载后要做三件事：

| 什么 | 怎么做 |
|---|---|
| **模型三件套** | 把 `create_app` 里的 LLM 缓存置空，下次 `get_llm()` 用新配置重建 |
| **日志级别** | 当场调 `logging.getLogger().setLevel(...)` |
| **巡检间隔 / 保留天数** | 不用做——它们是**每次用到时现读** |

### 配置怎么传到各处

`create_app` 现在把 `cfg` 直接捕获进闭包，改不了。改成**传一个 `get_cfg` 回调**——跟现成的 `get_llm` 一个路子，仓库里已经有这个注入了，再加一个不突兀。

`build_router(get_cfg, data_dir, organize_fn, get_llm)`。

### 反馈

保存后在窗口里直接给结果，**不刷新页面**：

- 成功：「已保存 · 模型已切到 `deepseek-flash`」
- 失败：逐条说哪个字段不行（比如日志级别只能是 INFO/DEBUG）

## 六、退出

点「退出」→ **弹确认** → 停服务 → 换成提示窗。

**顺序很重要：先答应，再退出。** 服务得先把 HTTP 响应发出去，然后才死——反过来页面拿不到响应，只会显示一个连接失败。

做法：起一个短延迟的定时器去执行「清掉 `service.json` + `os._exit(0)`」，端点立刻返回。

> **测试要能注入假的退出**，不然跑一次测试就把 pytest 自己杀了。`create_app` 收一个 `quit_fn`，默认是真退，夹具传假的。

## 七、路由与接口

| 路由 | 方法 | 干什么 |
|---|---|---|
| `/settings` | GET | 返回**模态窗的 HTML 片段**（不含整页骨架） |
| `/settings` | POST | 保存 + 重载，返回 JSON 结果 |
| `/quit` | POST | 停服务，返回 JSON |

**为什么 GET 返回片段而不是整页**：模态是从**任意页面**打开的，fetch 进来塞进遮罩层就行，不用跳页、也不用每个页面都背一份隐藏的窗口标记。

## 九、边界与错误处理

| 情况 | 怎么处理 |
|---|---|
| `.env` 不存在 | 创建它（从 `.env.example` 抄一份注释骨架） |
| 提交了只读字段（`KB_VAULT_PATH` / `KB_PORT`） | **忽略**，不改——前端不给改，后端也不信前端 |
| API Key 留空 | 不改那一项 |
| 日志级别填了别的值 | 拒掉，逐条报错 |
| 巡检间隔填了 0 或负数 | 拒掉 |
| 写 `.env` 失败（磁盘满、没权限） | 报错，**不重载**——文件没写成，内存里跟着变就成了两套真相 |
| `/quit` 之后页面还开着 | 页面的数据全来自服务，停了就是死的；提示窗负责告诉他关掉 |
| `/quit` 时正是别的请求在跑 | 不管。短延迟后硬退——反正下次 `kb` 调用会自动拉起 |

## 十、测试

- **`.env` 写回保留注释与顺序**：拿 `.env.example` 当样本，改一个键，逐行比对（除了那一行，其余一字不差）
- **文件里没有的键追加到末尾**
- **`.env` 不存在时能创建**
- **重载真的读到了新值**：写、重载、断言 `Config` 变了
- **重载后 LLM 缓存失效**：改模型名 → `get_llm()` 拿到的是新建的
- **API Key 不回显原文**：`GET /settings` 的 HTML 里**不含** key 明文
- **只读字段提交了也不改**：POST 里塞 `KB_VAULT_PATH`，断言 `.env` 没动
- **非法值逐条报错**：日志级别填 `TRACE` → 400 + 指明是哪个字段
- **`/settings` GET 返回片段**：含四组的标题，**不含** `<!doctype`
- **`/quit` 调的是注入的退出函数**，不是真退（否则跑一次测试杀一次 pytest）
- **巡检间隔从配置来**：`due()` 收到不同的 `interval_days` 结果不同
- **保留天数从配置来**：`prune` 收到不同的 `keep_days` 删掉的文件不同
