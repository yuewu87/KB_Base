# KN_Base

**一个给 AI 用的个人知识库。** 你在任何会话里随口说一句值得记的话，它自己判断放哪、写成什么、打什么标签；你要查的时候，让会话里的 AI 代你查，或打开网页直接问。

知识存在 `E:\KB_Library`（一个 Obsidian vault），代码在本仓库。两者物理分离，各自独立版本管理。

> **状态：核心链路全部打通**，测试全绿，真实 LLM 端到端验过。
> **细节以 [`docs/`](docs/) 为准**——本文只当入口，不重复那边的设计。

---

## 一、为什么不是「一个文件夹 + 手动分类」

**问题不在存不下，在找不到。**

文件夹的物理位置只能有一个，但一条知识天然属于多个上下文。「IE 缩放导致点击坐标算歪」这一条，属于浏览器自动化、属于坐标换算、属于 RPA 项目——放哪个文件夹都能说得通，放哪个都会在别的场景里想不起来。

所以这个库有三个前提：

| | |
|---|---|
| **人机共用，但偏 AI** | 人只用 Obsidian 做三件事：看、查、随手改。主要的读和写都是会话里的 AI |
| **本体是纯 markdown** | 没有数据库、没有隐藏格式，记事本能打开。Obsidian 只是它的一个视图，卸载了文件还在，git 历史还在 |
| **检索不靠文件夹，靠标签** | 文件夹决定「物理放哪」，标签决定「属于哪些主题」。**一篇能挂多个标签，不能放多个文件夹** |

最后一条是关键：**文件夹放错了也不影响找得到**。所以「AI 偶尔分错类」不再是致命问题，也就不需要逼人逐条审核。

## 二、有哪几块

```
   ┌────────────────┐              ┌────────────────┐
   │    会话层       │              │    Web UI      │
   │ Claude Code 等  │              │  随手记 / 看日志 │
   │  只投递、发请求  │              └───────┬────────┘
   └───────┬────────┘                      │
           │  kb push / kb organize         │
           └──────────────┬─────────────────┘
                          ▼
          ┌──────────────────────────────────┐
          │        知识库服务（本地进程）      │
          │   收下 → 判断放哪 → 写进库         │
          │   自带 LLM，不占你的会话额度       │
          └──────────────┬───────────────────┘
                         │ 读写 markdown 文件
                         ▼
          ┌──────────────────────────────────┐
          │      vault（E:\KB_Library）       │
          │   计算机/  艺术/  文学/            │
          │   _收件箱/  _索引/  _附件/         │
          └──────────────┬───────────────────┘
                         │ Obsidian 打开它
                         ▼
                   人（查看 / 检索 / 写判断）
```

**会话层和 Web UI 是平级的两个入口**——能力完全一样，只是走 shell 还是走浏览器。以后接 QQ bot 就是再加一个入口，内核不动。

**整理切成四段：** 规划（LLM）→ 校验（机器）→ 审核（只在**新建分类**时才调 LLM）→ 落盘（不调 LLM）。

> 完整设计（目录结构、笔记格式、标签规则、日志分层、为什么这么切……）见 [`docs/01_架构.md`](docs/01_架构.md)。

## 三、怎么用

### 装环境

```bash
conda create -n kn_base python=3.11 -y
conda activate kn_base
pip install -r requirements.txt
```

### 第一次用：开网页，点「初始化知识库」

```bash
cp .env.example .env        # Windows cmd: copy .env.example .env
```

`.env` 里**只需要填模型的三件套**：

```
KB_LLM_API_KEY=sk-...
KB_LLM_BASE_URL=https://api.deepseek.com
KB_LLM_MODEL=deepseek-flash
```

后两项 `.env.example` 里已经给了能用的值，换供应商才需要改。空着不会静默降级——
**除了 `kb stop`，每条 `kb` 命令都会当场停下**并说清缺哪一项。

然后双击 **`web.bat`**。**知识库还没建的时候，首屏会有一张引导卡**，点它上面的
「初始化知识库」会打开设置窗里那条龙，一屏三段填完：

| | |
|---|---|
| **① 模型配置** | 模型名 / API 地址 / API Key。旁边有「测试连接」，先测再存 |
| **② 知识库目录** | 填一个绝对路径。**目录不存在没关系，初始化时会建**。旁边的「检查」顺手验一下 |
| **③ 初始领域** | 九个候选里勾，**至少勾一个**。勾中的会建成一级目录 |

点「初始化」就齐了。它会建目录、写 `.gitignore`、把那个目录初始化成 git 仓库。
**幂等**——在一个已经有东西的目录上点它也不会毁掉什么。

之后那块面板就变成「已初始化」状态，上面挂着三个动作：**迁移到别处 / 打开目录 /
移除知识库**。

> **要加领域，不用改配置**：在资源管理器里给库建个一级文件夹就行，服务下次就认。
> 领域的唯一真源始终是磁盘。

<details>
<summary>不想用网页，走命令行也行</summary>

填好 `.env` 里的 `KB_VAULT_PATH`（**它没有默认值了**——不填就是「还没有知识库」，
每条命令都会停下告诉你去初始化），然后：

```bash
python scripts/init_vault.py <你的路径>
```

那个脚本是 vault 结构的唯一真源（实现住在 `src/kb/core/vault_setup.py`）——
想调目录就改它重跑，别手工建。**注意它只建目录，不写 `.env`**：配置一直是服务的活。
</details>

> vault 是**另一个 git 仓库，刻意不配远端**：里头是你的私人笔记，别顺手推到 GitHub。
> （本仓库的 `data/` 同理，整棵不进 git。）

### 起服务 / 开网页

**不用手动起。** 第一次调 `kb` 命令时它自己会拉起来，之后一直待在后台。

**双击 `web.bat`** 就能用——它确保服务在跑，然后把浏览器打开。**双击 `stop.bat`** 停掉它。

```bash
./kb.bat status     # 看它在不在、在哪个端口
./kb.bat stop       # 停掉
./kb.bat web        # 服务没跑就拉起来，然后把网页打开
```

网页侧栏底部也有一个红色的**退出**按钮，效果同 `stop`。

### 日常五条

```bash
kb push --content "并发写入会锁表，最后用队列串行化解决" --source 会话
kb push --content "这条结论要改……" --revise "队列串行化"
kb inbox                                  # 看攒了几条
kb organize
kb search "缩放"
kb drop 20260918-9e4f                     # 投错了就撤（可给多个 id）
```

**投递只交正文。** 类型、标签、放哪、叫什么名字——一概不填，那是整理阶段的事。一次投递 = 一条草稿，多条就调多次。

**投错了有退路。** `--project` 的默认值是猜的（取 git 根目录名），猜错很正常；`kb drop` 撤掉重投就行。

**谁决定什么时候整理：** 会话 AI 判断。规则写在 [`docs/接入指南/`](docs/接入指南/)——**那是会话层 AI 能读到的地方**（一份 skill），不是给人看的说明文档。

**改已有的笔记不会覆盖**：旧内容打失效标记保留、默认不再出现在检索结果里，这样能看出结论是怎么演变的。

### 网页

双击 **`web.bat`**，或直接开 `http://127.0.0.1:51823`。

| 页面 | 干什么 |
|---|---|
| **＋ 记一条** | 选个脚手架帮自己把话说清，写完点投递——**直接归位**，不用等 |
| **ai对话** | 说一句就行：「记一下…」「…是怎么说的」 |
| **整理日志** | 按天的**箱子**，右侧栏「报告 / 历史」两个竖排页签 |
| **工作日志** | 每一步干了什么，页签是「流程图 / 历史」 |
| **运行日志** | 技术输出，终端样式，只有箱子没有页签 |
| **巡检** | 定期收拾标签和目录的建议与报告；「巡检一次」也在这儿 |
| **设置** | 改模型、日志级别、巡检间隔——**保存即生效**（见下） |
| **退出** | 停服务（红底那个） |

**网页投的和 CLI 投的有个区别**：网页是亲手写的，写完就想看到结果，所以**投完直接走完整理**；CLI 那条是 agent 干活时投的，攒着，由会话 AI 挑时机。

## 四、配置

配置放工程根目录的 `.env`（**不入库**），照 `.env.example` 填一份。**第一次用先看上面的「第一次用」一节**——模型的 key 是必填的；vault 目录不用手工填，点「初始化知识库」时会自己写进来。

| 键 | 必填 | 说明 |
|---|---|---|
| `KB_LLM_API_KEY` | ✅ | LLM 的 API key。**没有默认值**，空着服务起不来 |
| `KB_LLM_BASE_URL` | ✅ | API 地址 |
| `KB_LLM_MODEL` | ✅ | 模型名 |
| `KB_VAULT_PATH` | | vault 路径。**没有默认值**——留空就是「还没有知识库」，网页上会显示成未初始化。正常不用手填，点「初始化知识库」时它会自己写进来 |
| `KB_PORT` | | 网页端口。**建议钉死**——留空的话每次重启换一个，收藏的网页地址就废了 |
| `KB_LOG_LEVEL` | | `INFO`（默认）/ `DEBUG`（排查时用） |
| `KB_SWEEP_INTERVAL` | | 距上次巡检超过几天自动跑一次，默认 `6` |
| `KB_LOG_KEEP_DAYS` | | 服务侧日志保留几天，更早的启动时清掉，默认 `90` |
| `KB_SKIN` | | 界面皮肤，默认 `archive`（现有的蓝）。见下面「界面皮肤」 |

**大部分不用手工改。** 网页侧栏的「设置」窗能改，而且**大部分保存即生效**：

| | |
|---|---|
| **当场生效** | 模型三件套、日志级别、界面皮肤 |
| **下次启动服务才生效** | 巡检间隔、服务侧日志保留——它们只在**服务启动那一刻**用一次（判要不要巡检、清过期日志） |
| **只读** | 端口。改了地址就变，收藏的网页地址就废了 |

设置窗里还有个 **[测试连接]**：拿表单里当前填的值试连一次，**先测再存**，不用为了验一次就把坏配置写进 `.env`。

> **`.env` 里的注释不会被动**——保存是逐行改值，注释、空行、顺序一律原样保留。

### 界面皮肤

界面有六套配色，**左栏底部的「外观」**点开就切，**选过就记住**（存进 `.env` 的 `KB_SKIN`）。
换皮肤整站当场变色，不刷新、也不用重启服务。默认是现有的蓝色；另外五套在设置窗
的「外观」一组里也能切——两个入口改的是同一件事。

| | |
|---|---|
| `archive` | 现有蓝（默认） |
| `dark-pink` | 炭黑 × 甜酷粉（深色） |
| `aurora` | 极光紫 × 蜜柚黄 |
| `garnet` | 石榴红 × 雾粉桃 |
| `neon` | 极光紫 × 荧光绿（深色） |
| `mono` | 黑皮（现有的蓝换到黑底上） |

**只改配色，布局一行不动。** 六套的取值不是手挑的：每套只有 6 个锚点是人定的，
其余 26 个由 [`src/kb/web/skins.py`](src/kb/web/skins.py) 按固定比例推出来，
`scripts/derive_skins.py` 写进 `style.css`，测试断言两边逐字相等——
**CSS 里那几块不要手改**，要调配色改 `skins.py` 再重跑脚本。

> 侧栏那根分隔线在浅色皮上是深色、在深色皮上是亮色——它是照着现有蓝那根
> （`#3d4753`）反推出来的镜像，不是随手挑的一档。

## 五、工程结构

```
KN_Base/
│
├─ 代码与工程 ───────────────────── 进 git
│  ├── src/kb/
│  │   ├── core/       ← 领域逻辑，不 import web/api
│  │   ├── llm/        ← LLM 抽象层，换供应商不改上层
│  │   ├── api/        ← 对外接口（薄层）
│  │   ├── web/        ← 管理界面
│  │   └── config.py   ← 读工程根目录 .env
│  ├── tests/          ← 测试（LLM 全 mock）
│  ├── scripts/        ← 建 vault 骨架、一次性迁移脚本
│  ├── templates/
│  │   ├── 笔记/        ← 笔记骨架 —— 机器读，套进笔记
│  │   └── 投递/        ← 随手记脚手架 —— 人读，帮他把话说清
│  ├── docs/           ← 设计文档，见下
│  └── .env.example · pyproject.toml · requirements.txt
│      kb.bat（命令行）· web.bat（双击开网页）· stop.bat（双击停服务）
│
└─ data/ ────────────────────────── **不进 git**
   运行数据：日志、会话历史、缓存、service.json
```

**为什么 `data/` 整棵排除：** 本仓库是 public 的，而运行数据里有会话历史——进去就是**公开发布**。
